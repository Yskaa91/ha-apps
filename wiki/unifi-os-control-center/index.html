Home

Overview

#home

UniFi OS Control Center is an experimental, local-first monitoring and management app for UniFi OS. It talks to your local UniFi Network integration API with a dedicated API key and is reachable only through Home Assistant Ingress.

#Current Scope

  • Ingress UI with navigation and inventory detail views
  • Sites, gateways, access points, clients, firmware inventory, raw API inspection
  • Legacy vs. Zone-Based Firewall capability detection
  • Read-only firewall policies, zones, diagnostics, analysis and local snapshots (Zone-Based Firewall only)
  • Persistent SQLite (WAL) telemetry and alert history with retention and row limits
  • Optional ntfy notifications; explicit device offline/recovery monitoring with grace polling
  • aarch64 and amd64, AppArmor profile, s6-overlay lifecycle
Firewall mutations stay behind explicit safety gates and are disabled by default. No undocumented legacy firewall endpoint is used.

Installation

Install the App

#installation

#Requirements

  • Home Assistant OS with Apps/Add-ons, on aarch64 or amd64
  • A UniFi OS console or UniFi Network Server reachable from the Home Assistant host over HTTPS
  • A dedicated UniFi API key

#Install

  1. Open Settings → Apps/Add-ons → Store and add the repository:
https://github.com/pol4rfuchs/ha-apps
  1. Reload the store, open UniFi OS Control Center, click Install.
  2. Set controller_url and api_key, keep verify_tls: true and read_only: true, save, start.
  3. Check the Log tab for errors, open the Web UI and run the connection test from the dashboard.
For a local source build, copy the complete app directory to /addons/unifi_os_control_center/ and comment out the image: line in config.yaml, otherwise the Supervisor tries to pull from GHCR. The prebuilt frontend/dist/ is required because npm is not run on the HAOS host.
🔌

Connect

Controller URL & API Key

#connect

#Controller URL

Use the local HTTPS address that opens the console in your browser — only the base URL:

https://<local-console-hostname-or-IP>

Do not append /network, /manage, /proxy/network or an API path, and do not use unifi.ui.com. The app itself calls <controller_url>/proxy/network/integration/v1/.

The Home Assistant host (not only your PC) must reach this URL. Across VLANs, allow TCP/443 (or your HTTPS port) from the HAOS network to the console.

#Create the API key

  1. Sign in directly to the local UniFi console, open Network → Settings → Integrations (on some versions under Control Plane → Integrations).
  2. Create a new key dedicated to this app and copy it immediately.
  3. Enter it in the api_key field. Never use your account password.
Use least privilege, never reuse a key from other scripts, and revoke it if it ever shows up in logs, screenshots or commits.

#Retention

Cleanup first deletes rows older than history_retention_days, then the oldest remaining rows while the database exceeds max_history_rows. Recommended polling: 15 balanced, 30–60 lower load, 5–10 faster but more requests.

#Safe initial configuration

controller_url: "https://your-unifi-console"
api_key: "paste-the-dedicated-api-key-here"
verify_tls: true
read_only: true
polling_interval: 15
history_retention_days: 30
max_history_rows: 100000
log_level: "INFO"

Safety

Read-Only & Firewall Gates

#safety

With read_only: true the backend rejects all non-read UniFi methods before the request is sent. Setting it to false only removes this local guard — it does not grant permissions the API key does not have.

read_only: true
allow_firewall_write: false
allow_firewall_delete: false
allow_policy_reorder: false
require_change_confirmation: true
create_prechange_snapshot: true

The Changes tab lists every condition currently blocking a mutation. These options alone do not make legacy firewall sites writable.

#Firewall analysis & snapshots

Analysis and snapshots run only when the site exposes the official Zone-Based Firewall API. Findings are advisory and never trigger changes. Snapshots store policies and zones in SQLite (WAL) with a SHA-256 integrity hash, and snapshot comparison reports added, removed and changed policies. On legacy firewall sites both stay unavailable.

Alerts

Alerts, ntfy & Device Health

#notifications

Alerts are always stored in SQLite; ntfy delivery is optional. Use Alerts → Test ntfy after restarting. The cooldown applies per event key. The Alerts page exports the bounded history as JSON or CSV (no API key or token included).

ntfy_enabled: true
ntfy_url: "https://your-ntfy-server.example"
ntfy_topic: "ha-alerts"
ntfy_token: ""
notify_on_connection_failure: true
notify_on_connection_recovery: true
notify_on_new_client: true
notification_cooldown: 900

#Device health

Only devices for which the official API returns an explicit online/offline state are monitored — no guessing. With device_offline_grace_polls: 2 and a 15 s polling interval the effective delay is about 30 seconds.

notify_on_device_offline: true
notify_on_device_recovery: true
device_offline_grace_polls: 2

Security

Security & Privacy

#security
  • The UI is reachable only through Home Assistant Ingress; the app has no login of its own and rejects connections that do not come from the Ingress gateway. No host port is published.
  • api_key and ntfy_token use the protected password schema and are never returned to the browser.
  • Keep verify_tls: true; prefer a trusted certificate or internal CA over disabling verification.
  • Assets are bundled locally: no Google Fonts, no CDN scripts, no analytics, no tracking.
  • Never commit options.json, API keys, backups or debug bundles with credentials.

#Storage & backup

Telemetry, alerts and snapshots live in /data/unifi_control_center.db (SQLite WAL). The app declares backup: hot, so Home Assistant backups include it without stopping the app. After a restore or migration, re-check routing/DNS and recreate the API key if needed.

#Local and external access

Local (LAN): reachable only through Home Assistant Ingress (sidebar). The app has no host port, and a guard rejects every request that does not come from the Supervisor's ingress gateway.

External (internet): never publish it. Reach it through Home Assistant itself (VPN or HA remote access).

Troubleshooting

Known Symptoms & Fixes

#troubleshooting
SymptomLikely causeFix
401 / 403Key incomplete, revoked, wrong console, or an account password was used.Create a new dedicated API key and re-enter it without spaces or line breaks.
404URL contains /network or /manage, or the Network version has no integration endpoint.Use only the console base URL; check Network → Settings → Integrations.
502 in the UIThe request to UniFi failed (DNS, refused, timeout, TLS, upstream HTTP error).Read the response detail and the app log for the underlying cause.
Certificate verification failedHostname mismatch, untrusted CA or broken chain.Fix the certificate; use verify_tls: false only temporarily for diagnosis.
Timeout / connection refusedConsole offline, wrong port, VLAN firewall, DNS not resolving from HAOS.Check routing and rules (TCP/443) and DNS from the HAOS network.
Works from a PC, not from the appDifferent DNS, inter-VLAN rules, hosts-file-only name, reverse-proxy allowlist.Test from the HAOS network, not from your PC.
No sites returnedKey has no access to the intended site, or API version mismatch.Check the key's scope and the app log.
Local install pulls from GHCRimage: is still active in config.yaml.Comment it out and reload the store.
For debugging use log_level: DEBUG and polling_interval: 30, then return to INFO. When reporting a bug, mask API keys, public and internal IPs, MAC addresses, SSIDs and client names.

Installation

Install the Add-on

#installation

#Prerequisites

  • MariaDB add-on (recommended): configure with a nextcloud database and user before the first start.
  • Port 8280 must be free on the host (or change it in the add-on config).

#Step 1 — Add Repository

https://github.com/pol4rfuchs/ha-apps

#Step 2 — Install & Configure

  1. Search for Nextcloud, click Install.
  2. Configure database options to match your MariaDB setup (see Configuration).
  3. Change admin_password from the changeme default before starting.

#Step 3 — Start

  1. Start the add-on.
  2. Open the Web UI — on first boot Nextcloud installs itself (~1–2 minutes).

Advanced

Shell & occ Access

#occ

For anything not exposed in the HA options UI, use the add-on's own shell (Settings → Add-ons → Nextcloud → three-dot menu, or the Terminal & SSH add-on's docker exec) and run occ directly:

php /var/www/html/occ config:system:set trusted_domains 1 --value="nextcloud.example.com"
php /var/www/html/occ config:system:set overwriteprotocol --value="https"

#How log_level Is Applied

The log_level option maps onto Nextcloud's numeric loglevel setting in config.php (0=Debug .. 4=Fatal). Since occ isn't usable until Nextcloud is installed, it's applied via the official image's hook mechanism:

  • docker-entrypoint-hooks.d/post-installation/10-set-loglevel.sh — runs once, right after the first install.
  • docker-entrypoint-hooks.d/before-starting/10-set-loglevel.sh — runs on every start, so changing the option later takes effect on the next restart.

Persistence

Data Layout & Backup

#persistence 
/data/nextcloud/
├── html/       # Nextcloud app code + config.php
└── data/       # User files (NEXTCLOUD_DATA_DIR)
A Home Assistant full backup (includes add-on data by default) already covers this. If backing up manually, back up the entire /data/nextcloud/ folder as a unit — config.php and the user data directory reference each other and should be restored together.

Security

Secrets & AppArmor Status

#security

#Secrets

OptionNote
admin_passwordDefaults to changeme — change before the very first start. Only applied during initial install; changing it afterwards in add-on options does not change the actual account password (use the Nextcloud UI or occ user:resetpassword).
db_passwordMust match whatever is configured on the MariaDB/Postgres side.

Both are declared as password schema types, so the Supervisor UI masks them.

#AppArmor — Not Yet Enforced

apparmor.txt is included but intentionally not yet enforced (apparmor: false) — this add-on runs on the official Nextcloud/Apache vendor image rather than the HA base image, and the profile's exact paths weren't verified against the real filesystem. See the profile's own header comment for the manual test steps before flipping it to true.

#Local and external access

Local (LAN): open http://<ha-host>:8280. Nextcloud only answers for hostnames in trusted_domains; anything else shows "Access through untrusted domain". The default covers homeassistant.local and homeassistant. If you open Nextcloud by IP, add the IP before the first start (the option is only applied on the first install; afterwards use occ). There is no ssl option, so use a reverse proxy for HTTPS.

External (internet): recommendation ok, but only through a reverse proxy with TLS. Never forward port 8280 directly. Add the public domain via occ config:system:set trusted_domains, set overwriteprotocol to https, and enable two-factor authentication for all accounts.

Troubleshooting

Known Symptoms & Fixes

#troubleshooting
SymptomCauseFix
"Access through untrusted domain" errorAccessing via a hostname/IP not in trusted_domains.Add it to trusted_domains, or use occ config:system:set trusted_domains.
Database connection failed on first bootdb_host/db_password don't match the MariaDB add-on.Verify the MariaDB add-on's database/user/password match the Nextcloud options exactly.
Install spins forever on first bootDB not reachable yet, or PHP memory too low.Confirm MariaDB add-on is running first; raise php_memory_limit if needed.
Upload fails on large filesmax_upload_size too low for the file.Increase max_upload_size (and check any reverse proxy's own upload limit too).
Changed admin_password option, login still failsOption only applies on the very first install.Reset the password via the Nextcloud UI or occ user:resetpassword instead.

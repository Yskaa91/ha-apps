Home

Overview

#home

Forgejo is a self-hosted, free Git platform — a community fork of Gitea. This add-on runs the official codeberg.org/forgejo/forgejo rootless image, exposed on port 3000 (no HA Ingress, assets break behind it) with optional SSH access for git clone/push.

Installation

Install the Add-on

#installation

#Step 1 — Add Repository

  1. Open Home Assistant.
  2. Go to Settings → Add-ons → Add-on Store.
  3. Open ⋮ → Repositories.
  4. Add:
https://github.com/pol4rfuchs/ha-apps

#Step 2 — Install

  1. Search for Forgejo in the Add-on Store.
  2. Click Install.

#Step 3 — Start & First-Run Wizard

  1. Start the add-on and open the Web UI via the sidebar.
  2. On first visit, Forgejo's own setup wizard runs — create the admin account there (not in HA options).
Forgejo manages its own admin account and users internally, created via its setup wizard, not through HA add-on options.

Advanced

app.ini Reference

#advanced

Anything not exposed in the HA options UI can be set directly in /config/conf/app.ini:

[service]
DISABLE_REGISTRATION = true

[packages]
ENABLED = true

[actions]
ENABLED = true

Or via environment variables applied automatically on start:

FORGEJO__service__DISABLE_REGISTRATION=true
FORGEJO__packages__ENABLED=true

Full reference: Forgejo configuration cheat sheet.

Persistence

Data Layout & Backup

#persistence 
/addon_configs/local_forgejo/   (host path)
/config/                        (inside the container)
├── conf/app.ini                ← Forgejo configuration (editable directly)
├── data/                       ← SQLite DB, packages, sessions
├── repositories/                ← Git repositories
├── ssh/                          ← SSH host keys
└── log/                           ← logs
A Home Assistant full backup (includes addon_configs by default) already covers everything above. To back up Forgejo alone, back up the entire /addon_configs/local_forgejo/ folder as a unit.

Security

AppArmor, SSH Keys & Secrets

#security

#AppArmor

A profile covering the s6-overlay baseline plus Forgejo's own runtime paths (/config, SSH host keys, git binaries) ships with the add-on, but AppArmor is currently disabled (apparmor: false) until the profile is re-tested on the Pi. Custom app.ini settings that make Forgejo read/write outside /config will need a matching rule once it is enabled again.

#Secrets

There's no dedicated password-type secret in this add-on's own options/schema — Forgejo manages its admin account and user credentials internally (created via its setup wizard, stored in data/). SSH host keys under ssh/ are generated on first start; treat them as sensitive if the /config/ folder is ever copied elsewhere.

#Local and external access

Local (LAN): open http://<ha-host>:3000 and set domain to the hostname or IP you use. For HTTPS inside the app set ssl: true (certificate and key from /ssl); the root URL is then https://<domain>/ without a port, so forward 443 to 3000 or use a reverse proxy.

External (internet): recommendation ok, but only through a reverse proxy with TLS. Never forward port 3000 or the SSH port directly. Registration is open by default, so set DISABLE_REGISTRATION = true before exposing the instance, and keep ssh_enabled off unless you need git over SSH.

Troubleshooting

Known Symptoms & Fixes

#troubleshooting
SymptomCauseFix
SSH clone/push failsssh_enabled is off, or port 22 clashes with the host's own SSH.Enable ssh_enabled; change ssh_port if 22 is already used by HA OS itself.
Repo clone URL or links show localhostdomain option left empty (the log shows a warning).Set domain to the hostname or LAN IP you open Forgejo with, or to the external hostname behind a reverse proxy.
Registration should be closed but isn'tNo UI toggle for this — needs app.ini.Set DISABLE_REGISTRATION = true under [service] in app.ini.

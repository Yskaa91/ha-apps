Home

Overview

#home

Matrix Authentication Service (MAS) by Element HQ delegates authentication of your Synapse homeserver via OIDC/OAuth2. It is the prerequisite for Element X QR-code login, MFA and further “Matrix 2.0” client features. This add-on runs it standalone next to matrix-synapse with a bundled PostgreSQL.

Status: untested / concept skeleton. According to the add-on's own documentation, a first build and test run (PostgreSQL init, mas-cli database migrate, mas-cli config sync) is still pending. Do not rely on it in production yet.
📋

Prerequisites

Before You Start

#prerequisites
  • A running Matrix Synapse add-on with Simplified Sliding Sync support (native since Synapse 1.114)
  • An own subdomain for the account UI (mas_domain)
  • Fresh start recommended: existing accounts are not migrated automatically — there is no syn2mas step in this add-on
🚀

Installation

Setup

#installation
  1. Install the add-on and set mas_domain, synapse_server_name and synapse_endpoint.
  2. Leave synapse_secret empty. It is generated on first start (shown in the log and stored in /data/mas/.synapse_secret).
  3. In the Synapse add-on set:
mas_enabled: true
mas_secret: <generated value>
mas_endpoint: http://[HA-IP]:8082
  1. Restart both add-ons.

Ports

Ports & Reverse Proxy

#ports
PortPurpose
8082/tcpMAS public API and account UI — put it behind your reverse proxy for HTTPS (same pattern as Synapse).
8083/tcpMAS internal: health and metrics, not meant for the reverse proxy.
Creating the reverse-proxy route for mas_domain (e.g. in Nginx Proxy Manager) is still an open item in the add-on documentation.

#Local and external access

Local (LAN): the account UI runs on port 8082 (http://<ha-host>:8082). MAS uses https://<mas_domain>/ as its public address (issuer), so the login flow only works through that HTTPS domain, not through the bare LAN IP. To use it locally, add a DNS rewrite for the domain to your local DNS server and put a reverse proxy with a certificate in front.

Reverse-proxy route (for example Nginx Proxy Manager): create a proxy host with domain = mas_domain, scheme http, forward host = your HA host, port 8082. Request a certificate and enable "Force SSL". Port 8083 (health check only) does not belong in the proxy.

External (internet): recommendation ok, only through the reverse proxy with TLS (Matrix clients need the public address). Never forward ports 8082 or 8083 directly. Keep password_registration_enabled off (default).

Backup

Database Backup

#backup

With backup_enabled the add-on periodically runs pg_dump on its bundled PostgreSQL database (own instance on port 5433, database mas) every backup_interval_hours, writes compressed dumps to /data/mas/backups and keeps backup_retention_days days of them. The first run starts about two minutes after add-on start. The live mas/postgresql/pg_wal directory is excluded from Home Assistant backups.

Home

Overview

#home

Unbound is a validating, recursive, caching DNS resolver from NLnet Labs. This add-on wraps it in a self-managed web UI — every setting (blocklists, whitelist, local records, network/performance/cache/security tuning) is configured through the dashboard, not YAML.

#Minimum Operating Model

Clients → Unbound :5053 (tcp/udp) → recursive resolution or forward
HA Ingress → Web UI :2137 → /data/config.json (blocklists, records, settings)
Unbound has no local TCP web server on the DNS port itself — the web UI runs on its own ingress port (2137), completely separate from DNS traffic on 5053.

Installation

Install the Add-on

#installation

#Step 1 — Add Repository

  1. Open Home Assistant.
  2. Go to Settings → Add-ons → Add-on Store.
  3. Open ⋮ → Repositories.
  4. Add:
https://github.com/pol4rfuchs/ha-apps

#Step 2 — Install

  1. Search for Unbound in the Add-on Store.
  2. Click Install.

#Step 3 — Start

  1. Optionally set log_level (default: info).
  2. Enable Start on boot, click Start.
  3. Open the Web UI via the HA sidebar (Ingress, port 2137).

#Step 4 — Point Clients at It

DNS itself listens on 5053 (not the standard 53), so point your router/DHCP or individual clients at the HA host's IP on port 5053. Some routers only support port 53 for upstream DNS forwarding — in that case set Unbound as a forwarder behind another resolver, or NAT-redirect 53→5053 at the firewall.

Port 5053 was chosen deliberately to avoid clashing with a host that already runs something on 53 (e.g. systemd-resolved, another DNS add-on).

Web UI

Dashboard & DNS Management

#webui

#Dashboard

Hero cards show total queries, cache hit rate, and blocked domains at a glance. A server info bar tracks uptime, thread count, average recursion time, prefetches, and unwanted queries. Donut charts break down query types (A, AAAA, MX, …) and response codes (NOERROR, NXDOMAIN, …). Dark mode is default.

Advanced

Custom Config & Overlay Files

#custom-config

Two ways to go beyond what the GUI exposes, both stored under /addon_configs/<slug>_unbound/:

#Full Custom Config

Enable Custom Config in the web UI, then place a complete unbound.conf at the addon config path. When enabled, all GUI settings are ignored — you own the whole file.

#Overlay Files

Keep GUI-managed settings but inject extra directives the GUI doesn't expose (whole top-level sections like auth-zone: or view:):

addon_configs/<slug>_unbound/unbound-overlay.conf   # extra server: directives
addon_configs/<slug>_unbound/unbound-extra.conf     # extra top-level sections

#Validation & Safe Fallback

Every combined configuration is checked with unbound-checkconf before use. If it fails, the add-on automatically falls back to GUI-only settings and surfaces the validation error in the Advanced tab — a bad snippet never takes DNS resolution down.

Persistence

Data & Backup

#persistence

All runtime configuration lives in /data/config.json, managed exclusively through the web UI — blocklists, whitelist entries, local DNS records, server settings, query log data.

/data/config.json   # add-on's own persistent storage — survives restarts, updates, container recreation automatically
No extra map: entry is required for /data — it's the add-on's own storage. A Home Assistant full backup already includes it, and there are no secrets to manage: Unbound needs no credentials, and the web UI relies on Ingress/HA auth rather than a separate login.

External access

Local and external access

#external-access

Local (LAN): DNS listens on 5053 (tcp/udp). Point your router, AdGuard upstream or clients at <ha-host>:5053. The web UI is Ingress-only (port 2137 is not mapped) and relies on the Home Assistant login; it has no login of its own, so the app rejects every request that does not come from the Ingress gateway. By default only private networks may query the resolver (access control).

External (internet): never forward 5053. An open resolver can be abused for DNS amplification attacks. If your router can only forward port 53, use a NAT redirect inside the LAN only.

Troubleshooting

Known Symptoms & Fixes

#troubleshooting
SymptomCauseFix
Clients get no DNS resolutionClients still pointed at port 53, not 5053.Update client/router DNS target to <HA-IP>:5053, or NAT-redirect 53→5053.
DNSSEC validation failuresUpstream forward server doesn't support DNSSEC, or system clock is wrong.Check NTP sync; try a DNSSEC-capable forwarder or pure recursive mode.
Port 5053 already in useAnother service (e.g. another DNS add-on) bound the port first.Change the add-on's port mapping in Network settings.
Blocklist changes not applyingRefresh not triggered after edit.Use the one-click refresh & apply button in the web UI.
Custom config rejectedunbound-checkconf validation failed.Check the error shown in the Advanced tab; the add-on falls back to GUI-only settings automatically.
